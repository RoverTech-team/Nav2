Phase 2b Proposal EKF Sensor Fusion + Visual Yaw Correction — Add to Existing AMCL + Raw Odom

Status: Proposed — ready for implementation after review  |  ROS 2: Humble  |  Robot: Skid-steer rover, ZED 2i camera, diff_drive controller

Problem

The robot currently has no sensor fusion. The localization chain is:

AMCL (laser map) ──► map→odom TF ✓ works diff_drive controller ──► /diff_drive_controller/odom └── publishes odom→base_footprint TF ✗ no yaw correction └── Nav2 consumes raw odometry ✗ heading drifts over time

Wheel odometry alone drifts in heading (especially on skid-steer). AMCL provides map-level correction but at low rate. There is no mid-rate heading correction between wheel ticks.

Proposed Solution

Insert a robot_localization EKF between the diff_drive controller and Nav2, fusing three parallel sensor streams:

BEFORE AFTER ┌──────────────────────┐ ┌──────────────────────────┐ │ │ │ AMCL ──► map→odom │ │ AMCL ──► map→odom │ │ │ │ │ │ diff_drive ──┐ │ │ diff_drive ──► │ │ ZED IMU ─────┤ │ │ Nav2 (raw odom) │ │ ├──► EKF ──┤ │ │ │ ArUco yaw ───┘ /odom │ │ odom→base_footprint:│ │ /filtered│ │ diff_drive pub │ │ │ │ │ │ │ Nav2 │ └──────────────────────┘ │ odom→base_footprint: │ │ EKF publishes │ │ diff_drive: disable TF│ └──────────────────────────┘

The Attitude Node (New)

attitude_node.py — A Python ROS 2 node that computes differential yaw from wall-mounted ArUco markers. It lives in the existing aruco_detection package.

Inputs: /aruco/markers (PoseArray), /aruco/marker_ids (Int32MultiArray), /odometry/filtered (EKF yaw for latch reference)

Output: /aruco/attitude (PoseWithCovarianceStamped, yaw-valid only)

All base frames: base_footprint (already used by AMCL, costmaps, diff_drive)

Data Flow

1 Subscribe to all three inputs
2 Look up zed_camera_link → base_footprint TF (cached)
3 For each marker: rvec → rotation matrix → wall normal → psi = atan2(normal.y, normal.x) in base_footprint
4 Latch: if not latched (first detect OR loss > 0.5 s): store psi_ref = circular_mean(all psi), yaw_ref = latest EKF yaw
5 Differential yaw: yaw_obs = yaw_ref + circular_delta(psi_mean − psi_ref) — no absolute azimuth
6 Inter-marker check: reject frame if |psi_i − psi_j| > yaw_threshold
7 Jump rejection: reject if |yaw_obs − last_published| > jump_threshold
8 Dynamic covariance: rolling window N → stddev → clamp(min_cov, max_cov) → covariance[35]
9 Publish /aruco/attitude
10 Loss recovery: no markers > 0.5 s → reset latch → re-latch on next detection

Vibration Robustness

The ZED IMU is sensitive to chassis vibration on rough terrain. Three mitigations:

  1. EWMA low-pass filter on IMU angular velocity in EKF config
  2. sigmas tuned above spec — real-world noise > spec sheet values
  3. Dynamic ArUco covariance — when vibration causes jump rejections, covariance rises → EKF naturally trusts visual input less → relies more on IMU + wheel odometry

IMU frame check: Run tf2_echo zed_camera_link zed_imu_link to verify alignment. Set imu0_remove_gravitational_acceleration: true if gravity is present in IMU data.
