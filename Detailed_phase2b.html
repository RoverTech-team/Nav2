1. attitude_node.py — CREATE

src/aruco_detection/aruco_detection/attitude_node.py

Design

A ROS 2 Python node that computes differential yaw from wall-mounted ArUco markers. Unlike yaw_test_node.py, it does not require a priori wall azimuths — it tracks relative yaw changes via a latching mechanism.

Additionally, it acts as a ZED point cloud rate relay — subscribing to the detection_node's adaptive mode status and adjusting the ZED wrapper's depth.point_cloud_freq parameter to save bandwidth when the robot is close to markers.

Subscriptions

TopicTypePurpose
/aruco/markersPoseArrayMarker poses from detection_node
/aruco/marker_idsInt32MultiArrayMarker ID list (aligned with poses)
/aruco/detection_statusFloat64MultiArrayAdaptive mode (data[2]) for point cloud rate control

Publications

TopicTypePurpose
/aruco/attitudePoseWithCovarianceStampedYaw estimate with dynamic covariance (pose.x/y/z = 0, orientation = yaw-only quaternion, frame_id: odom)

Services Called

ServiceTypePurpose
/zed/zed_node/set_parametersrcl_interfaces/SetParametersSet depth.point_cloud_freq based on current adaptive mode

Data Flow — Yaw Estimation

1 Receive marker poses + IDs
2 Look up zed_camera_link → base_footprint TF (cached, identity fallback on failure — same pattern as yaw_test_node)
3 For each valid marker ID: rvec → wall normal → transform to base_footprint → psi = atan2(normal.y, normal.x)
4 Inter-marker check: reject frame if max pairwise |psi_i - psi_j| > yaw_threshold
5 Latch logic: if not latched (first valid detection OR loss > loss_timeout):
  psi_ref = circular_mean(all psi)
  yaw_ref = 0.0 (absolute yaw is irrelevant)
  Set latched = True
6 Differential yaw:
  psi_mean = circular_mean(all psi)
  yaw_obs = yaw_ref + circular_delta(psi_mean - psi_ref)
  (circular_delta normalizes to [-180, 180))
7 Jump rejection: skip if |yaw_obs - last_published| > jump_threshold
8 Dynamic covariance: rolling window of last N accepted yaws → stddev → clamp(min_cov, max_cov) → set covariance[35] (yaw-yaw cell)
9 Publish /aruco/attitude as PoseWithCovarianceStamped (zero translation, yaw-only quaternion, header.frame_id = "odom" — EKF world_frame)
10 Loss recovery: if no valid markers for > loss_timeout seconds → reset latched flag, clear rolling covariance deque → re-latch on next detection (covariance starts high after recovery)

Data Flow — Point Cloud Rate Control

11 On /aruco/detection_status: store adaptive_mode = msg.data[2] (0=disabled, 1=2K, 2=1080, 3=720, 4=VGA)
12 Every pointcloud_update_interval (3 s):
   rate = pointcloud_rate_map[adaptive_mode]
   try: call set_parameters({depth.point_cloud_freq: rate}) on ZED node
   except: pass — ZED node may be down; retry next cycle

7b-ii. Failure forget timeout

Add parameter:

self.declare_parameter("failure_forget_timeout", 10.0)

In the step-down section (when _consecutive_misses >= _stepup_frames), before checking distance/angle tolerances:

time_since_detection = (now - self._last_detection_time).nanoseconds * 1e-9
if time_since_detection > self._failure_forget_timeout:
    self._failed_res_idx = -1  # forget past failure, retry climb
    self.get_logger().info("Failure forget timeout — will retry higher resolution")

Without this, the robot spends 83% of time at 720p because the failure memory (_failed_res_idx) permanently blocks re-ascent to 2K at the same pose. After 10 s, the robot has likely moved to a new area where 2K would succeed.

Load Analysis

Point Cloud Bandwidth Comparison

ConfigurationPoints/framePublish ratePoints/secvs Current
Current (HD720, COMPACT, 30 Hz)~230K30 Hz~6.9MBaseline
HD2K, REDUCED, 10 Hz static~685K10 Hz~6.85M≈ same
HD2K, REDUCED, dynamic 10→3 Hz~685K3–10 Hz~2–7M29–100%

Key insight: At HD2K REDUCED 10 Hz, the point cloud data rate matches the current HD720 COMPACT 30 Hz configuration (~6.9M pts/sec). The depth computation is handled by the ZED SDK on the GPU regardless of publish resolution — the savings are in USB/memory bandwidth for point cloud serialization and transport.

When the attitude_node dynamically lowers point_cloud_freq to 3 Hz (VGA mode, robot close to markers), the data rate drops to ~2M pts/sec — a 71% reduction from current. This directly frees Jetson memory bandwidth for the detection pipeline.

ros2 topic echo /odometry/filtered --once
ros2 topic info /aruco/attitude
ros2 topic info /odometry/filtered

3. Yaw Correction During Manual Rotation

With the robot off the ground or on a turntable, rotate manually while watching:

ros2 topic echo /odometry/filtered --field pose.pose.orientation
ros2 topic echo /diff_drive_controller/odom --field pose.pose.orientation

The raw odometry heading drifts while /odometry/filtered is corrected by the ArUco yaw.

4. Dynamic Covariance Behavior

ros2 topic echo /aruco/attitude --field pose.covariance

covariance[35] should rise when markers are far/noisy and fall when close/stable.

5. Loss Recovery

Cover the camera for 2+ seconds, then uncover. The log should show a re-latch message and yaw should resume without a discontinuity.
